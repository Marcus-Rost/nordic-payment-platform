# JRPay iOS — customer mobile client

Native iOS (Swift + SwiftUI + Combine) customer client for JRPay. Phase 4C
of the GUI extension; feature-parity with the Web and Android clients
(UC-G01…UC-G29).

## Stack

| Concern              | Choice                                          |
| -------------------- | ----------------------------------------------- |
| Language             | Swift 5.9                                        |
| UI                   | SwiftUI + Combine                                |
| Build                | Xcode 15 (iOS 17 deployment target)              |
| Networking           | URLSession + async/await + Codable               |
| Auth                 | OAuth2 PKCE + ASWebAuthenticationSession (BankID)|
| Token storage        | Keychain (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`) |
| SCA                  | Dynamic-linking (RFC 8785 + SHA-256 via CryptoKit) |
| Biometric unlock     | LocalAuthentication / Face ID / Touch ID         |
| Offline cache        | URL-derived path under Library/Caches            |
| Tests                | XCTest                                            |

## Build

The full iOS app target requires **Xcode 15+** on macOS. The
`JrpayCore` SPM target — which holds the dynamic-linking hash that has to
stay byte-identical with the Java/web/Android clients — also builds and
tests on Linux, so CI can verify cross-platform parity without a Mac
runner.

### macOS (full app)

```bash
cd implementation/ios-app
# Open in Xcode
open Package.swift   # or open the .xcodeproj once generated

# CLI build
xcodebuild -scheme Jrpay -sdk iphonesimulator17.0 build
xcodebuild test -scheme Jrpay -sdk iphonesimulator17.0 \
  -destination 'platform=iOS Simulator,name=iPhone 15'
```

### Linux (JrpayCore only — DlHash parity tests)

```bash
# Install Swift via swiftly (one-time setup)
curl -fsSL https://download.swift.org/swiftly/linux/swiftly-$(uname -m).tar.gz \
  | tar xz -C /tmp
/tmp/swiftly init --assume-yes
export PATH="$HOME/.local/share/swiftly/bin:$PATH"

cd implementation/ios-app
swift build           # JrpayCore + swift-crypto
swift test            # runs JrpayCoreTests/DlHashTests (8 tests)
```

`Package.swift` hides the iOS-only `Jrpay` target on non-Apple platforms
via `#if os(macOS)`, so `swift build` on Linux compiles only the Foundation
+ `Crypto` (swift-crypto) target and never tries to import SwiftUI.

The `Package.swift` describes the source layout for SwiftPM-based
typechecking and tooling. The actual app target needs an Xcode project
(`Jrpay.xcodeproj`) with:

- iOS 17 deployment target
- Bundle id `no.jrpay.client`
- Capabilities: Keychain Sharing (`no.jrpay.client.session`),
  Push Notifications, Associated Domains (for universal-link app-links)
- URL Types: scheme `jrpayclient` (matches the OAuth redirect URI)
- Info.plist:
  - `NSFaceIDUsageDescription` (UC-G27)
  - `CFBundleLocalizations` = `en, nb`
  - `LSApplicationQueriesSchemes` for BankID app-handoff (future)

## Configuration

`AppDependencies.shared` holds the identity + API base URLs. For local
development against the JRPay docker-compose stack you have two options:

1. **iOS simulator** can talk to the host directly via `http://localhost:8097`
   etc. — no special configuration needed.
2. **Physical device** needs the LAN IP of the host running compose. Edit
   the URLs in `AppDependencies.swift` or wire them through `Info.plist`
   for per-flavor builds.

## Security notes

- **Tokens**: Keychain with `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`
  → unavailable when the device is locked, and not transferred between
  devices via iCloud Keychain backup.
- **PII**: `OfflineCache` only stores already-redacted server payloads.
  Tokens are never written to disk outside the Keychain.
- **SCA**: every payment / mandate / R2P-accept / GDPR-erasure runs the
  dynamic-linking flow. Swift `DlHash` is byte-identical to the Java
  services + web + Android; verified by
  `Tests/JrpayCoreTests/DlHashTests.swift` (Linux-buildable).
- **OAuth**: BankID redirect through `ASWebAuthenticationSession` (system-
  hosted browser sandbox); deep-link callback via custom URL scheme.
- **Network**: ATS is enforced — production must use HTTPS.
